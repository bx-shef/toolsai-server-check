# toolsai-server-check — проверить свой сервер

Два небольших скрипта проверяют, подходит ли ваш сервер Битрикс24 для модулей [Tools AI](https://b24-crm-tools-ai.bx-shef.by/) (подробнее — на [странице shef.toolsai](https://b24-crm-tools-ai.bx-shef.by/toolsai)) и для своих сервисов (распознавание звонков, лёгкая модель, чтение файлов).

Оба скрипта **только читают**. Они ничего не меняют на сервере и ничего не отправляют наружу, кроме проверочных HTTPS-запросов без данных. Единственное изменение — кнопка «Удалить файл» в `toolsai_check.php` удаляет сам скрипт.

| Файл | Что проверяет | Как запустить |
|---|---|---|
| `toolsai_check.php` | портал: PHP и расширения, версии Битрикс24 и модулей, cron для агентов, исходящий HTTPS, диск, память PHP | скачать в корень портала, открыть в браузере под администратором |
| `toolsai_check.sh` | сервер: ядра, память, AVX2, диск, Docker, виртуализация/LXC, порты | см. «Быстрый старт» |

## Быстрый старт

Проверка делается **на сервере клиента**, где стоит (или будет стоять) Битрикс24. Скрипты ничего не отправляют: результат читает тот, кто запустил проверку, и сам видит, что исправить.

### Сервер: ядра, память, диск, Docker

Зайдите на сервер по SSH и вставьте одну строку (через `curl`):

```bash
curl -fsSL https://github.com/bx-shef/toolsai-server-check/releases/latest/download/toolsai_check.sh | bash
```

или через `wget`:

```bash
wget -qO- https://github.com/bx-shef/toolsai-server-check/releases/latest/download/toolsai_check.sh | bash
```

Если сначала хотите прочитать скрипт — скачайте и запустите отдельно:

```bash
curl -fsSLO https://github.com/bx-shef/toolsai-server-check/releases/latest/download/toolsai_check.sh
bash toolsai_check.sh
```

Отдельная виртуальная машина только под сервисы (Битрикс24 на другой):

```bash
curl -fsSL https://github.com/bx-shef/toolsai-server-check/releases/latest/download/toolsai_check.sh | bash -s -- --services-only
```

### Портал: PHP, модули, cron, исходящий HTTPS

```bash
cd /home/bitrix/www && wget https://github.com/bx-shef/toolsai-server-check/releases/latest/download/toolsai_check.php
```

Откройте `https://ваш-портал/toolsai_check.php`, войдя под администратором. Без входа администратора файл отвечает отказом. Прочитав результат, удалите файл:

```bash
rm /home/bitrix/www/toolsai_check.php
```

(или нажмите на странице «Удалить файл»).

### Как выглядит результат

Для каждой проверки: что проверено, найденное значение, норма и знак — ✓ в порядке, ⚠ стоит проверить, ✗ нужно исправить. Если что-то не так, под строкой — что сделать. В конце — сводка: готов сервер к Tools AI или нет и какие пункты исправить.

Сервер подходит:

```
Tools AI — проверка сервера (toolsai_check.sh 1.1.3). Скрипт только читает, ничего не меняет и не отправляет.

Режим: Битрикс24 и сервисы на одной ВМ.
Знаки: ✓ в порядке, ⚠ стоит проверить, ✗ нужно исправить.

Ресурсы (норма: минимум / средний / запас):
  ✓ Ядра процессора: 12 (норма 8 / 12 / 16)
  ✓ Память: 24 ГБ (норма 16 / 24 / 32)
  ✓ Свободный диск: 36 ГБ (норма +20 / +30 / +50 ГБ сверх Битрикса)
  ✓ Процессор, AVX2: есть (норма нужна поддержка AVX2)

Окружение:
  ✓ Docker: установлен (норма должен быть для своих сервисов)
  ✓ Виртуализация: kvm (норма kvm, none или другая полная)
  ℹ Занятые порты (TCP): 22 80 443. Порты сервисов не должны пересекаться с ними.

Уровень по ресурсам: средний

=== Сводка ===
Итог: готово — сервер подходит для Tools AI.
```

Сервер не подходит:

```
Tools AI — проверка сервера (toolsai_check.sh 1.1.3). Скрипт только читает, ничего не меняет и не отправляет.

Режим: Битрикс24 и сервисы на одной ВМ.
Знаки: ✓ в порядке, ⚠ стоит проверить, ✗ нужно исправить.

Ресурсы (норма: минимум / средний / запас):
  ✗ Ядра процессора: 4 (норма от 8)
      → добавьте ядра виртуальной машине или возьмите сервер мощнее
  ✗ Память: 8 ГБ (норма от 16 ГБ)
      → увеличьте память виртуальной машины
  ✗ Свободный диск: 15 ГБ (норма от +20 ГБ сверх Битрикса)
      → освободите место или расширьте диск
  ✓ Процессор, AVX2: есть (норма нужна поддержка AVX2)

Окружение:
  ⚠ Docker: не найден (норма нужен для своих сервисов)
      → установите Docker (если свои сервисы не нужны — можно пропустить)
  ✓ Виртуализация: kvm (норма kvm, none или другая полная)
  ℹ Занятые порты (TCP): 22 80. Порты сервисов не должны пересекаться с ними.

Уровень по ресурсам: ниже минимума

=== Сводка ===
Итог: не готов к Tools AI. Исправьте:
  ✗ ядра: есть 4, нужно от 8
  ✗ память: есть 8 ГБ, нужно от 16 ГБ
  ✗ диск: свободно 15 ГБ, нужно от 20 ГБ
Проверьте:
  ⚠ Docker не установлен: нужен, если запускаете свои сервисы
```

Страница `toolsai_check.php` показывает то же самое таблицей: проверено, найдено, норма и подсказка под строкой, внизу — итог.

## Что проверяет `toolsai_check.php`

- версия PHP и расширения `curl`, `json`, `mbstring`, `openssl`, `zlib`;
- версии модулей Битрикс24: `ai` не ниже 26.1000, `crm` не ниже 26.800, модуль `im` установлен;
- агенты работают на cron;
- исходящий HTTPS до `license.bx-shef.by`;
- исходящий HTTPS до адреса модели — добавьте в адрес параметр: `https://ваш-портал/toolsai_check.php?model=https://адрес-модели`;
- свободное место на диске (минимум +20 ГБ сверх Битрикса);
- `memory_limit` PHP.

## Что проверяет `toolsai_check.sh`

Нужен для своих сервисов, которые PHP из браузера не видит: ядра, память, поддержка AVX2 (без неё модели не запускаются), свободный диск, Docker, тип виртуализации (в LXC на Proxmox нужны `nesting=1` и `keyctl=1`) и занятые порты.

### Уровни

Нагрузку при всех своих сервисах (распознавание, лёгкая модель, файлы) выдерживают три уровня:

| | Минимум | Средний (советуем) | С запасом |
|---|---|---|---|
| Ядра | 8 | 12 | 16 |
| Память | 16 ГБ | 24 ГБ | 32 ГБ |
| SSD сверх Битрикса | +20 ГБ | +30 ГБ | +50 ГБ |
| Распознавание | turbo | large-v3 | large-v3 |
| Для кого | до ~10 сотрудников | 10–50 | 50+ |

Добавки к основе Битрикс24 (4–8 ГБ) по функциям:

| Сервис | Память | Ядра |
|---|---|---|
| Модули Tools AI в портале | почти ничего сверху | — |
| Модель в облаке по ключу | ничего сверху | — |
| shef.cowork (MCP-сервер) | +0,2–0,5 ГБ | мало |
| Чтение файлов и сборка документов | +1,5 ГБ | 1–2 |
| Своё распознавание звонков | +3 ГБ (turbo) / +6 ГБ (large-v3) | 3–6, ограничивать |
| Своя лёгкая модель | +4 ГБ | сколько отдали, ограничивать |
| Эмбеддинги | +0,3 ГБ | 2 |

Типовая виртуальная машина Битрикс24 на 4 ядра и 8 ГБ подходит модулям с моделью в облаке; свои сервисы она не потянет. Для своих сервисов нужен Docker на сервере портала или рядом.

Память скрипт округляет до ближайшего ГБ: виртуальная машина «16 ГБ» показывает чуть меньше.

## Две ВМ: Битрикс24 отдельно, сервисы отдельно

Таблица уровней выше — для одной ВМ, где живут и Битрикс24, и сервисы. Если Битрикс24 на своей ВМ, а сервисы (распознавание, лёгкая модель, файлы) на другой, проверка идёт на каждой своим режимом:

| ВМ | Что на ней | Что запустить |
|---|---|---|
| ВМ 1 — Битрикс24 | портал и модули Tools AI (модель в облаке сверху почти ничего не берёт, Docker не нужен) | `https://ваш-портал/toolsai_check.php?layout=split` |
| ВМ 2 — сервисы | Docker и наши контейнеры | `sudo bash toolsai_check.sh --services-only` |

Пороги для ВМ 2 — расчёт по таблице добавок выше (сумма памяти сервисов и ядра, которые днём нужны распознаванию, файлам и эмбеддингам). Уровня «с запасом» для ВМ 2 нет:

| | Минимум | Средний |
|---|---|---|
| Память | 10 ГБ (turbo) | 13 ГБ (large-v3) |
| Ядра | 6 | 10 |
| SSD | +20 ГБ | +30 ГБ |

Портал обращается к сервисам по частной сети. Сервисы по умолчанию слушают `127.0.0.1`; при раздельных ВМ адрес меняется на внутренний, а порты закрываются файрволом от всех, кроме ВМ портала. В режиме `?layout=split` свободный диск ВМ портала показывается справочно, без порога.
