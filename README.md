# toolsai-server-check — проверить свой сервер

Два небольших скрипта проверяют, подходит ли ваш сервер Битрикс24 для модулей [Tools AI](https://b24-crm-tools-ai.bx-shef.by/) (подробнее — на [странице shef.toolsai](https://b24-crm-tools-ai.bx-shef.by/toolsai)) и для своих сервисов (распознавание звонков, лёгкая модель, чтение файлов).

Оба скрипта **только читают**. Они ничего не меняют на сервере и ничего не отправляют наружу, кроме проверочных HTTPS-запросов без данных. Единственное изменение — кнопка «Удалить файл» в `toolsai_check.php` удаляет сам скрипт.

| Файл | Что проверяет | Как запустить |
|---|---|---|
| `toolsai_check.php` | портал: PHP и расширения, версии Битрикс24 и модулей, cron для агентов, исходящий HTTPS, диск, память PHP | открыть в браузере под администратором |
| `toolsai_check.sh` | сервер: ядра, память, AVX2, диск, Docker, виртуализация/LXC, порты | `sudo bash toolsai_check.sh` |

## 1. Проверка портала — `toolsai_check.php`

1. Положите файл в корень портала (обычно `/home/bitrix/www/`).
2. Откройте `https://ваш-портал/toolsai_check.php`, войдя под администратором. Без входа администратора файл отвечает отказом.
3. Страница показывает таблицу: ✅ в порядке, ⚠️ стоит проверить, ❌ не хватает, ℹ️ справочно.
4. В конце — итог: «готово» или «не хватает: …».
5. Нажмите «Удалить файл» — скрипт удалит сам себя. Если прав на удаление нет, удалите файл вручную.

Что проверяется:

- версия PHP и расширения `curl`, `json`, `mbstring`, `openssl`, `zlib`;
- версии модулей Битрикс24: `ai` не ниже 26.1000, `crm` не ниже 26.800, модуль `im` установлен;
- агенты работают на cron;
- исходящий HTTPS до `license.bx-shef.by`;
- исходящий HTTPS до адреса модели — добавьте в адрес параметр: `https://ваш-портал/toolsai_check.php?model=https://адрес-модели`;
- свободное место на диске (минимум +20 ГБ сверх Битрикса);
- `memory_limit` PHP.

## 2. Проверка сервера — `toolsai_check.sh`

Нужна для своих сервисов, которые PHP из браузера не видит. Запускайте на сервере пользователем с `sudo`:

```bash
sudo bash toolsai_check.sh
```

Скрипт показывает ядра, память, поддержку AVX2 (без неё модели не запускаются), свободный диск, наличие Docker, тип виртуализации (в LXC на Proxmox нужны `nesting=1` и `keyctl=1`) и занятые порты.

### Уровни

Нагрузку при всех своих сервисах (распознавание, лёгкая модель, файлы) выдерживают три уровня:

| | Минимум | Средний (советуем) | С запасом |
|---|---|---|---|
| Ядра | 8 | 12 | 16 |
| Память | 16 ГБ | 24 ГБ | 32 ГБ |
| SSD сверх Битрикса | +20 ГБ | +30 ГБ | +50 ГБ |
| Распознавание | turbo | large-v3 | large-v3 |
| Для кого | до ~10 сотрудников | 10–50 | 50+ |

Добавки к основе Битрикс24 (4–8 ГБ) по функциям:

| Сервис | Память | Ядра |
|---|---|---|
| Модули Tools AI в портале | почти ничего сверху | — |
| Модель в облаке по ключу | ничего сверху | — |
| shef.cowork (MCP-сервер) | +0,2–0,5 ГБ | мало |
| Чтение файлов и сборка документов | +1,5 ГБ | 1–2 |
| Своё распознавание звонков | +3 ГБ (turbo) / +6 ГБ (large-v3) | 3–6, ограничивать |
| Своя лёгкая модель | +4 ГБ | сколько отдали, ограничивать |
| Эмбеддинги | +0,3 ГБ | 2 |

Типовая виртуальная машина Битрикс24 на 4 ядра и 8 ГБ подходит модулям с моделью в облаке; свои сервисы она не потянет. Для своих сервисов нужен Docker на сервере портала или рядом.

Память скрипт округляет до ближайшего ГБ: виртуальная машина «16 ГБ» показывает чуть меньше.

### Итог скрипта

```
Уровень по ресурсам: средний
Итог: готово
TAI1;cpu=12;mem=24;disk=36;avx2=1;docker=1;virt=kvm;level=mid;ok=1
```

Итог — «готово» или «не хватает: …». Последняя строка — код проверки: в нём только числа и тип виртуализации, без имён, адресов и ключей.
